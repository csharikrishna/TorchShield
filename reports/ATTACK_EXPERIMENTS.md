## Experiment 1: Equivalent Keys & Entropy Collapse in Legacy Key Schedule

### Hypothesis
The legacy chaotic key schedule initializes state via `((seed % (p - 3)) + 3) % p`. Consequently, seeds differing by multiples of $(p - 3)$ collapse to identical trajectories, bounding the effective key space to at most $p - 3 \approx 2^{32}$ states.

### Method & Execution
- Initialized three `AHCC_Engine` instances with seeds:
  - $S_1 = 100$
  - $S_2 = 100 + (p - 3) = 4,294,967,388$
  - $S_3 = 100 + 2(p - 3) = 8,294,967,388$
- Generated round keys for $N=8, R=2, p=4,294,967,291$.

### Observed Result
`torch.equal(engine1.round_keys, engine2.round_keys) == True`  
`torch.equal(engine1.round_keys, engine3.round_keys) == True`  
**Result:** PASSED. The key schedule collapses high-entropy master seeds into a single 32-bit state modulo $p-3$. The claim of 128-bit or 256-bit security under the legacy chaotic mode is mathematically refuted.

## Experiment 2: State Recovery via Key Schedule Inversion

### Hypothesis
The recurrence $x_{m+1} = a x_m^2 + b x_m + c \pmod p$ is algebraically invertible: given an observed state $x_{m+1}$, the previous state $x_m$ can be recovered by solving a degree-2 polynomial over $\mathbb{F}_p$ using Tonelli-Shanks modular square root.

### Method & Execution
- Evaluated step: $x_{\text{curr}} = 987,654,324 \to x_{\text{next}} = 3,134,943,955 \pmod p$.
- Inverted using:
  $$\Delta = b^2 - 4a(c - x_{\text{next}}) \pmod p$$
  $$\sqrt{\Delta} = \Delta^{(p+1)/4} \pmod p \quad (\text{since } p \equiv 3 \pmod 4)$$
  $$x_{\text{candidate}} = (-b \pm \sqrt{\Delta}) \cdot (2a)^{-1} \pmod p$$

### Observed Result
Candidate 1: $987,654,324$ (Matches $x_{\text{curr}}$ exactly).  
Candidate 2: $3,307,312,964$.  
**Result:** PASSED. The key schedule is non-cryptographic and can be inverted step-by-step backward in $O(1)$ arithmetic operations.

## Experiment 3: Ciphertext Malleability & Zero-Integrity Silent Corruption

### Hypothesis
Direct `AHCC_Engine` encryption provides no message authentication or integrity tags. An attacker modifying ciphertext bits causes decryption to output corrupted plaintext with zero detection or error.

### Method & Execution
- Plaintext: $[10, 20, 30, 40, 50, 60, 70, 80]$.
- Ciphertext generated by `engine.encrypt(pt)`.
- Flipped 1 element in ciphertext: $c_0' = (c_0 + 1) \pmod p$.
- Invoked `engine.decrypt(ct_tampered)`.

### Observed Result
- No exception was raised.
- Decrypted plaintext returned: $[2683935293, 1686738590, 3088927051, 1493011388, \dots]$.
- Corrupted plaintext silently released to downstream application.  
**Result:** PASSED. AHCC direct mode violates INT-CTXT and is vulnerable to active adversarial tampering.

## Experiment 4: Deterministic ECB-like Information Leakage

### Hypothesis
Because direct `AHCC_Engine` is an un-keyed permutation without IV/nonce, identical input vectors produce identical ciphertext vectors, leaking statistical frequency patterns in model weights.

### Method & Execution
- Created a 2-vector batch where $V_1 = V_2 = [1, 2, 3, 4]^T$.
- Encrypted via `engine.encrypt(batch)`.

### Observed Result
`torch.equal(ct[:, 0], ct[:, 1]) == True`.  
**Result:** PASSED. Identical vectors yield identical ciphertexts, failing IND-CPA security.
